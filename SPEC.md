# Verto — техническое задание (v1)

> **Verto** — лат. «поворачиваю; перевожу». Оба смысла — суть приложения:
> перевод и автоматический разворот направления.

Минималистичный переводчик для macOS, живущий в строке меню.
Главный принцип: **вставил текст — получил перевод. Ни одного лишнего действия.**

---

## 1. Проблема

Существующие решения не подходят:

| Приложение | Почему не подошло |
|---|---|
| MATE | Перестало работать (завязка на неофициальный веб-эндпоинт) |
| TransOne | Всё устраивает, но платное |
| GoogleTranslate (dbilgili) | Нужно **вручную переключать направление** перевода; неподходящий дизайн |

**Ключевая боль:** в окне выставлено `RU → EN`, вставляешь английскую фразу — приложение
не понимает и переводит мусор. Нужно лезть и переключать направление. Это стоит времени
на каждой второй операции.

## 2. Решение

1. **Направления перевода не существует как настройки.** Пользователь выбирает *пару*
   языков (по умолчанию `RU ⇄ EN`). Приложение определяет язык введённого текста
   и переводит его в противоположный язык пары.
2. **Локальный движок.** Apple `Translation.framework`: бесплатно, офлайн,
   языковые пакеты скачиваются один раз — то же, за что берёт деньги TransOne.
   Нет API-ключей → любой человек скачал и пользуется.
3. **Строка меню + глобальный хоткей.** Приложение всегда под рукой, не занимает Dock.

## 3. Область v1

### 3.1 Входит

- Иконка в menu bar, попап по клику
- Глобальный хоткей вызова попапа (по умолчанию `⌥⌘T`)
- Поле ввода с автофокусом при открытии
- Автоопределение языка и направления внутри выбранной пары
- Автоперевод по мере ввода (debounce 300 мс)
- Копирование результата одним движением (`⌘↩` — скопировать и закрыть)
- Ручной разворот направления (`⌘S` / клик по индикатору) — на случай ошибки определения
- Предупреждение при низкой уверенности определения языка
- Отдельная индикация скачивания языкового пакета
- Автозапуск при входе в систему
- Настройки: пара языков, хоткей, автозапуск
- Нативный macOS-дизайн (см. §6)

### 3.2 Не входит (v2+)

- Перевод скриншота через OCR (`Vision.framework`)
- Озвучка (TTS)
- Опциональный движок DeepL по своему API-ключу
- Подпись и нотаризация Apple Developer
- Перевод выделенного текста в стороннем приложении по хоткею (требует Accessibility)
- Автоперевод из буфера обмена

## 4. Функциональные требования

### FR-1. Определение языка

Метод определения выбирается **по свойствам выбранной пары**, а не задаётся жёстко:

**Случай А — письменности пары не пересекаются** (RU↔EN, JA↔EN, AR↔FR и т.п.):
язык определяется по написанию.

- Учитываются **только** буквы, принадлежащие письменностям одного из двух языков пары.
  Цифры, пунктуация и посторонние алфавиты не голосуют.
- Доля букв первого языка ≥ **15%** → текст считается первым языком.

Язык может иметь **несколько** письменностей: японский пишется каной и кандзи сразу,
и учёт только одной из них дал бы неверный счёт.

**Обоснование:** `NLLanguageRecognizer` ненадёжен на коротких строках
(`«OK»`, `«Pizza»`, `«Ping»`) — это воспроизвело бы исходную боль. Алфавитный метод
здесь даёт практически 100% точность и нулевую задержку. Порог 15%, а не 50%,
потому что типичный рабочий русский текст содержит много английских терминов
(«задеплой на staging через CI»).

**Случай Б — письменности пересекаются** (EN↔DE, RU↔UK, JA↔ZH):
алфавитный метод неприменим в принципе, используется `NLLanguageRecognizer`.
На коротких строках возможны ошибки — см. FR-6.

**Важно:** это не «RU↔EN по алфавиту, остальное как получится». Детектор проверяет
письменности пары и выбирает метод сам. Наивная проверка «есть ли кириллица»
на паре RU↔UK давала бы 100% ошибок.

### FR-2. Перевод

Движок — `Translation.framework`, **прямой API без привязки к SwiftUI**:

```swift
TranslationSession(installedSource:target:)   // macOS 26+
session.cancel()                              // macOS 26+
```

Два режима работы:

| Ситуация | Проверка | Поведение |
|---|---|---|
| Пакет установлен | `LanguageAvailability.status(from:to:)` → `.installed` | Прямая сессия, перевод сразу |
| Пакет не скачан | → `.supported` | Разовый путь через `.translationTask` + `prepareTranslation()`, система показывает диалог скачивания |
| Пара не поддерживается | → `.unsupported` | Сообщение в интерфейсе, перевод не запускается |

Требования к запросам:

- Debounce 300 мс после последнего нажатия клавиши.
- **Перед новым запросом предыдущий отменяется** штатным `session.cancel()` —
  иначе системный движок получает запрос на каждое нажатие и начинает троттлить.
- Пустой ввод → пустой результат, без запроса.

### FR-3. Ввод и вывод

- Поле ввода получает фокус автоматически при открытии попапа.
- `⌘V` работает как обычно, перевод стартует сразу после вставки.
- `↩` — перенос строки (**не** триггер перевода).
- Результат — выделяемый текст, доступный для копирования мышью.
- `⌘↩` — скопировать перевод в буфер и закрыть попап.
- `esc` — закрыть попап.
- `⌘S` — принудительно развернуть направление.

### FR-4. Индикатор направления

Над полями отображается определённое направление, например `RU → EN`. Обновляется
в реальном времени по мере ввода. Клик по индикатору разворачивает направление вручную.

Индикатор должен читаться как кликабельный: курсор `pointingHand` при наведении,
подсветка при hover. При этом он **не должен попадать в область выделения текста** —
это отдельный контрол над полями, а не часть текстового потока.

**Зачем:** пользователь всегда видит, что именно приложение решило, и может
исправить это одним движением, не открывая настройки.

### FR-5. Настройки

- Пара языков — любые два из 19 языков, поддерживаемых Apple (по умолчанию `Русский ⇄ English`)
- Глобальный хоткей, переназначаемый: клик по полю, нажатие сочетания, готово.
  По умолчанию `⌥⌘T` — **не** `⌥Space`, он занят Raycast и Alfred.
  Сочетание обязано содержать `⌘`, `⌥` или `⌃`: без них оно срабатывало бы при
  обычном наборе текста в любом приложении. Один `⇧` не считается — `⇧T` это просто `T`.
  Если система отказала (сочетание занято), об этом сообщается в настройках.
- Запускать при входе в систему (`SMAppService`)

### FR-6. Предупреждение о низкой уверенности

Если определение языка ненадёжно, рядом с индикатором направления показывается
ненавязчивый значок-предупреждение с подсказкой «направление определено
предположительно, ⌘S — развернуть».

Срабатывает когда:
- используется `NLLanguageRecognizer` (случай Б в FR-1) и его уверенность ниже порога;
- либо доля букв «своей» письменности близка к порогу 15% (смешанный текст).

**Зачем:** пользователь может ввести текст на языке вне выбранной пары (французский
при паре RU↔EN) — приложение примет его за английский и переведёт на русский.
Предупреждение делает эту ситуацию видимой вместо молчаливо неверного результата.

### FR-7а. Управление языковыми пакетами

В настройках для выбранной пары показывается состояние пакетов и кнопка загрузки:

| Состояние | Что видит пользователь |
|---|---|
| Проверка | «Проверка…» со счётчиком |
| Установлены | Зелёная отметка «Установлены» |
| Не загружены | Текст «Не загружены» и кнопка **Скачать** |
| Загрузка | «Загрузка…» со счётчиком |
| Не поддерживается | Какой именно язык Apple не переводит |
| Ошибка | Причина и кнопка **Ещё раз** |

Пакеты **направленные**, поэтому загружаются оба направления пары —
последовательно, иначе два системных диалога наложатся друг на друга.

Программного вызова загрузки у Apple нет: единственный путь — держать сессию из
`.translationTask` и вызвать `prepareTranslation()`, что и показывает системный
диалог подтверждения. Поэтому объект `LanguagePacks` решает, **что** качать,
а вид, которому он принадлежит, выполняет саму загрузку.

### FR-7. Индикация скачивания языкового пакета

При первом переводе для новой пары скачивание пакета занимает время. В интерфейсе
показывается отдельное состояние «загрузка языка», визуально отличное от «перевод идёт»,
чтобы приложение не выглядело зависшим. Состояния различаются по `LanguageAvailability`
(см. FR-2).

### FR-9. Пустое окно при каждом открытии и история

Попап **всегда открывается пустым**. Оставшийся с прошлого раза текст пришлось бы
стирать перед тем, как вставить новый, — то есть лишнее действие ровно там, где
приложение обещает их отсутствие.

Ничего не теряется: при закрытии — любом, включая `esc` и клик мимо — завершённый
перевод уходит в историю.

**История:**

- До 50 записей, новые сверху.
- Повторный перевод того же текста **поднимается наверх**, а не добавляется копией.
  Иначе закрытие и открытие на одной фразе забило бы список одинаковыми записями.
- Клик по записи возвращает её в поля, готовой к копированию.
- Удаление записи — через контекстное меню, очистка всей истории — кнопкой.
- Пустой исходник или пустой перевод не сохраняются.

В поле ввода есть кнопка очистки, показывается только когда есть что стирать.

### FR-10. Перевод текста с экрана

Значок прицела в шапке попапа и пункт в меню значка. Порядок действий:

1. Попап убирается с экрана — иначе он закрывает то, что нужно снять.
2. Появляется системный прицел (`screencapture -i`): тот же, что у `⌘⇧4`,
   с пробелом для перемещения выделения и `esc` для отмены.
3. Выделенная область распознаётся `Vision.RecognizeTextRequest`.
4. Попап возвращается с распознанным текстом, дальше всё как при вставке:
   определение направления, перевод.

Отмена — штатный исход, а не ошибка: окно просто возвращается в прежнее состояние.

**Языки распознавания задаются по выбранной паре и в её порядке** — Vision использует
порядок для разрешения неоднозначностей.

Vision называет языки с регионом (`ar-SA`, `vi-VT`, `zh-TW`), поэтому сравнение идёт
**по коду языка**, а не по полному идентификатору. Сравнение целиком не совпадало бы
никогда, список уезжал бы пустым, и Vision молча читал бы всё как английский.

Из 19 языков Verto распознаётся 18: **хинди Vision не поддерживает**. Для
неподдерживаемых языков подставляется английский, иначе запрос ушёл бы с пустым
списком.

**Распознанный текст попадает в редактируемое поле, а не переводится вслепую.**
Короткие заглавные последовательности OCR путает (`CI` читается как `Cl`), и это
свойство распознавания, а не ошибка реализации — проверено на обоих режимах языковой
коррекции. Пользователь видит текст до того, как заберёт перевод, и может поправить.

**Требуется разрешение на запись экрана.** Запрашивается при первом снимке.

### FR-8. Высота попапа

Ширина фиксирована — 360 pt. Высота ведёт себя так:

- **Базовая высота 300 pt** держится, пока текст помещается в поля. Окно не прыгает
  при каждой вставке.
- **Длинный текст растягивает окно вниз**, до потолка **520 pt**.
- Дальше поля скроллятся внутри себя, окно больше не растёт.
- Растягивается только то поле, которому не хватило места; второе сохраняет базовую
  высоту, чтобы перевод не уезжал из поля зрения.

**Обоснование:** фиксированная высота тратит место на коротких фразах, полностью
плавающая — дёргает окно при каждой вставке. Порог даёт стабильность в типичном
случае и не обрезает длинный текст.

## 5. Нефункциональные требования

| Требование | Значение |
|---|---|
| Задержка от вставки до перевода | < 500 мс |
| Работа без интернета | Обязательна (после скачивания языкового пакета) |
| Потребление в покое | Фоновая активность отсутствует; работа только при открытом попапе |
| Минимальная версия ОС | **macOS 26** (прямой API `Translation.framework`; см. Р-10) |
| Архитектуры | Apple Silicon + Intel (universal binary) |
| Приватность | Текст не покидает устройство. Никакой телеметрии |
| Лицензия | MIT |

## 6. Дизайн

Приложение должно выглядеть как штатная утилита macOS, а не как «портированный сайт».

- Фон попапа — **`NSGlassEffectView`**, стиль `.regular` (Liquid Glass, macOS 26).
  Не имитация средствами слоёв: системный материал сам даёт рефракцию, отклик на
  подложку и корректное поведение при смене обоев и темы
- Скругление 18 pt (радиус Liquid Glass), контролы внутри — капсульные
- Только системные шрифты (`.body`, `.callout`) и системные цвета
  (`.labelColor`, `.secondaryLabelColor`) — корректная работа в светлой и тёмной темах
- Стандартные контролы AppKit/SwiftUI без кастомной отрисовки
- Иконка в menu bar — SF Symbol, шаблонный режим (перекрашивается системой)
- Размер попапа ~360×300 pt, поля ввода и вывода разделены тонким разделителем
- Никаких брендовых цветов, градиентов и анимаций сверх системных
- Иконка в menu bar имеет **три** состояния: покой, попап открыт, скачивание пакета.
  Состояния «низкая уверенность» у иконки нет — см. Р-14

## 7. Архитектура

```
Verto/
├── Package.swift
├── Makefile                    # сборка .app-бандла без Xcode
├── Sources/Verto/
│   ├── VertoApp.swift          # @main, LSUIElement
│   ├── MenuBarController.swift # NSStatusItem + NSPopover
│   ├── HotKey.swift            # Carbon RegisterEventHotKey (без Accessibility)
│   ├── LanguageDetector.swift  # FR-1, выбор метода по паре
│   ├── TranslationService.swift# FR-2, прямой API, debounce + cancel()
│   ├── Settings.swift          # UserDefaults + SMAppService
│   └── Views/
│       ├── PopoverView.swift
│       └── SettingsView.swift
├── Resources/Info.plist
├── README.md
└── LICENSE                     # MIT
```

**Замечание по `Translation.framework`:** используется прямой API
(`TranslationSession(installedSource:target:)`), поэтому сервис перевода **не зависит
от SwiftUI** и тестируется отдельно от интерфейса. SwiftUI-модификатор `.translationTask`
остаётся только на разовом пути скачивания языкового пакета (FR-2).

**Глобальный хоткей** реализуется через Carbon `RegisterEventHotKey`, а не через
`NSEvent` global monitor — первый не требует разрешения Accessibility.

**Иконки:** каталог ассетов (`.xcassets`) не используется. Иконка в menu bar — SF Symbol,
иконка приложения — `.icns`, собираемый через `iconutil` (входит в Command Line Tools).
Это убирает зависимость от `actool` и связанный с ним класс проблем сборки без Xcode.

## 8. Сборка и распространение

- Сборка через SwiftPM + `Makefile`, собирающий `.app`-бандл. **Xcode не требуется**
  (на машине есть Command Line Tools со Swift 6.3 и нужными SDK).
- `Makefile` создаёт `Verto.app/Contents/{MacOS,Resources}`, кладёт бинарник,
  `Info.plist`, `PkgInfo` и `.icns`, затем подписывает.
- Ad-hoc подпись: `codesign --force -s - Verto.app`. **Без `--deep`** — Apple не
  рекомендует его для подписи, а для бандла с одним бинарником он и не нужен.
- В README — команда снятия карантина для скачавших:
  `xattr -dr com.apple.quarantine /Applications/Verto.app`
- Релизы на GitHub: `.dmg` + исходники.
- Полноценная подпись и нотаризация Apple Developer ($99/год) — решение отложено до v2.

## 9. Риски

| Риск | Оценка | Митигация |
|---|---|---|
| Ручная сборка `.app`-бандла без Xcode | **Выше среднего** | **Первый шаг реализации — минимальный скелет.** Проверяем сборку, подпись и запуск до написания логики. Отказ от каталога ассетов снимает зависимость от `actool`. При провале — ставим Xcode |
| `SMAppService` не работает с ad-hoc подписью | **Высокий** | Проверяется в том же первом прототипе. Автозапуск требует валидной подписи, и ad-hoc может не проходить. Запасной путь — `LaunchAgent`-plist в `~/Library/LaunchAgents`. Если не решится — функция уезжает в v2 вместе с подписью |
| `Translation.framework` троттлит при частых запросах | Средний | Debounce 300 мс + штатный `session.cancel()` (FR-2) |
| Ошибки определения языка для пар с одинаковой письменностью | Средний | `NLLanguageRecognizer` + видимое предупреждение о низкой уверенности (FR-6). Дефолтная пара RU↔EN этому не подвержена |
| Текст на языке вне выбранной пары | Низкий | Предупреждение о низкой уверенности (FR-6); полное решение — в v2 |
| Качество Apple-перевода ниже DeepL | Низкий | Для RU↔EN приемлемо; в v2 — опциональный DeepL по своему ключу |
| Требование macOS 26 отсекает часть аудитории | **Принято осознанно** | Решение Р-10. Цена за чистую архитектуру и штатную отмену запросов |
| Gatekeeper блокирует неподписанное приложение | Принято | Инструкция в README; подпись в v2 |

## 10. Критерий готовности v1

Открыть попап хоткеем, вставить фразу на английском, следом фразу на русском —
и оба раза получить корректный перевод, **ни разу ничего не переключив**.
